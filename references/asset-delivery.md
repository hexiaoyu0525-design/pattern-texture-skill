# AI 资产双通道交付与归档（asset-delivery）

> **重要前提**：本文件所有建议都是参考，不是硬标准。没有绝对的"高级/廉价"，也没有绝对的"对/错"——先想清楚你想要的是什么风格，再判断这些规则适不适用。一切以你的需求为准。

> 归属：pattern-texture-skill · 作用域：**pts 全部 AI 生成/编辑产物，无例外**——纹样图、肌理特写、配色色卡、四方连续拼接测试图、成衣效果等一切图片产物；不限于某一类纹样或某一种工艺。
> 前置：纹样设计流程走 `design-workflow.md`；出图提示词走 `prompt-templates.md`；翻车诊断走 `pattern-diagnosis.md`；版权合规走 `copyright-guide.md`。
> 版本：1.0 · 许可 CC BY 4.0

## 一、核心动作（工具中立，任何平台/Agent 通用）

**pts 的每一张 AI 生成或编辑产物，完成"生成"不等于完成——推荐同时完成两个动作（可按项目规模裁剪，小批量一次性图可合并）：**

1. **拿到产物句柄**：生成工具返回的原始短链 / URL / 本地文件（建议逐字使用工具返回值，不下载、不重传、不换链——换链容易断、丢血缘）。
2. **持久归档**：把产物写入可跨会话找回的位置——云端画布 / 云盘语义目录 / 本地素材库与项目文件夹。归档目录按语义组织（纹样母版、历史版本、交付物分开）。
3. **可见交付**：把产物**直接展示**给用户（对话框媒体卡片 / 图片预览 / 文件卡片），不是只给路径或文字描述。

> 参考判定：产物未归档 + 未直接展示，通常视为"未交付"。缺一个就补一个；小型一次性项目可按用户习惯简化，但建议至少留一个可找回的位置。

## 二、豆包办公默认实现（画布写入 + 本地归档 + 对话框展示）

> 豆包办公的实现 = **一条原始产物短链，三端同落**：① design-cli 画布写入（持久化 + 画布展示）→ ② 本地项目文件夹归档（持久存档）→ ③ 对话框媒体卡片展示（可见交付）。三端共用**同一条工具返回值**，不下载、不重传、不换链。换环境见第四节。

### 1. 绑定画布（初始化）
- 当前对话已有唯一有效 `canvas_workspace_id` 时直接复用；没有时调用 `design-cli design-workspace +workspace-create --title "<标题>"` 建一张，从响应 XML 读唯一 ID，并由主 Agent 用 `present_files(<workspace_id>)` 交付画布卡片（**不得**创建 workspace-id.txt 等中间文件）；画布卡片交付成功前不得生成/编辑媒体、不得执行 Item/Frame 写命令。
- `+get-workspace` 只用于显式查询、恢复或排障，不代替"对话无 ID 时必须创建"的初始化规则。

### 2. 画布写入（持久化分支，Agent 必做）
- 把生成工具返回的原始短链写进画布——`design-cli design-workspace +create-batch --canvas-workspace-id <画布ID> --input -`，stdin 传 XML：

```xml
<batch>
  <items>
    <item type="IMAGE" path="/generated-assets/<语义名>" title="<短名>" brief="<一句话摘要，供判断是否回读>">
      <size width="1672" height="1672" />
      <asset url="<生成工具返回的原始短链>" />
    </item>
  </items>
  <frames></frames>
</batch>
```
- 写入后必须 `design-cli design-workspace +get --canvas-workspace-id <画布ID> --item-ids <返回ID>` 回读，核对 URL/type/path/title/brief 与对象 ID。`title` 是端上给用户的短名、`brief` 是给自己消费的判断字段，两者不要填成一样。
- 批量**全成或全败**：单次 XML ≤1MB、单批对象 ≤50（顶层 Item + Frame + 成员合计），超限直接拒、不截断。
- 衍生图在 `<source_ids>`（成员 `<source_id>`）里声明来源 Item/Frame ID——只 `+create` 系生效，服务端用它决定落位，不只是记血缘。
- **交付分支**：主 Agent 将生成工具返回的**同一条原始短链**通过媒体卡片（RichMediaCard）逐项展示；可批量（≤6 张/组）展示，逐项确认。用户"看到图"以此为准，不得只给路径或文字描述代替。

### 3. 本地项目文件夹归档（持久存档分支，默认并行）
- 同一产物**同时**落进当前项目文件夹对应阶段目录，命名 `风格_纹样名_类型_版本_日期`；这是跨会话找回的持久存档，画布只是它的镜像。无画布环境时本节独立承担"持久归档"。

### 4. 语义目录（画布 path 与本地目录对应）
- **画布顶层四类**（path 必须以 `/` 开头，写不存在的 path 自动构成目录，无需 mkdir）：
  - `/user-anchors`（用户上传的原始锚点：参考纹样、面料照片、灵感图）
  - `/core-assets`（核心资产母版：`/core-assets/<纹样名>/master`）
  - `/generated-assets`（可复用生成资产）
  - `/deliverables`（最终交付物）
- **本地对应**按纹样项目阶段：`01_灵感参考/`（参考图/灵感板）、`02_纹样设计/`（设计稿/配色方案/工艺建议）、`03_出图成品/`（纹样图/肌理特写/成衣效果）、`00_项目画布/`（进度看板/设计记录）；**各阶段目录下含 `定稿版/`**（用户拍板确认的图复制一份）；`_历史版本_<风格>/`（旧版移入，可回滚）。

### 5. PTS 特有产物归档清单

> 纹样项目和普通出图不一样，有几类特殊产物必须单独归档：

| 产物类型 | 为什么必须单独存 | 命名建议 |
|---|---|---|
| **四方连续主图** | 纹样母版，后续所有衍生都基于它 | `风格_纹样名_四方连续_主图_v1.png` |
| **无缝拼接测试图** | 把主图拼 3×3 看接缝，验证能不能用 | `风格_纹样名_拼接测试_3x3.png` |
| **配色色卡图** | 主色/辅助色/点缀色的 HEX 色值，方便后续打样 | `风格_纹样名_配色色卡_v1.png` |
| **面料肌理特写** | 微距图，能看到织纹/光泽/凹凸，用于工艺参考 | `风格_纹样名_肌理特写_v1.png` |
| **成衣效果参考** | 纹样穿在人身上的效果，看比例和密度对不对 | `风格_纹样名_成衣效果_v1.png` |
| **工艺方案图** | 印花/刺绣/提花等不同工艺的效果对比 | `风格_纹样名_工艺对比_v1.png` |

> 不是每个项目都要全有，按实际产出归档。至少保留：主图 + 拼接测试图 + 配色色卡。

### 6. 版本与血缘规则
- 同一纹样衍生 N 个变体 = N 次独立生成/编辑调用（每次同一锚点），不用单次多结果代替。
- 内容修改后的新版本 = 新文件 / 画布新 Item（版本号递增），不覆盖旧版；旧版移入本地 `_历史版本_<风格>/` 或画布历史区，可回滚。
- 衍生图用 `<source_ids>` 记录血缘并决定画布落位；`+update` 只改顶层 brief/path，不改内容，不补血缘。

## 三、出图模型选择（默认平台）

> 详见 SKILL.md「生成工具与入口」。本节只列纹样场景的特殊判断：

| 场景 | 推荐模型 | 为什么 |
|---|---|---|
| 四方连续纹样（高精度） | Seedream 5.0 Pro | 无缝拼接的边缘细节很重要，Pro 精度更高 |
| 面料肌理特写（微距） | Seedream 5.0 Pro | 织纹/光泽/凹凸的细节是核心，不能糊 |
| 配色方案预览 | 5.0 Flash / 标准版 | 快速看配色方向，不用高精度 |
| 成衣效果参考 | Seedream 5.0 Pro | 服装版型 + 纹样位置 + 面料质感，综合度高 |
| 草稿/快速迭代 | 5.0 Flash / 标准版 | 省时间，快速看大方向 |

> 原则：**最终交付用 Pro，中间预览用 Flash**。纹样的细节（线条精细度、颜色准确度、无缝拼接质量）直接决定能不能用，建议不要为了省时间用低精度模型出最终版。

## 四、其他环境降级（工具中立）

- **无 design-cli / 无画布环境**：跳过画布写入，归档落在本地项目文件夹或云盘语义目录（`项目/纹样/<纹样名>/`），交付用平台的图片/文件展示能力。
- 核心动作不变：句柄 → 归档 → 可见交付。只是"画布"换成"文件夹/云盘"。
- 换 Agent / 平台时按各自的能力映射做对应调整。
