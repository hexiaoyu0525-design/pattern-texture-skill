# PTS 评测集（8 条主任务 + 2 条附加）

**用途**：每次改完 SKILL 或 references 后跑一遍，看三件事有没有退化——**触发**（该不该由本技能接）、**路由**（该读哪几份文件、有没有多读）、**产出**（交付物的硬判据）。

**怎么跑**：把「用户这么说」原样当输入，不看技能文档先自己走一遍，再对照「期望路由」；产出侧按「判据」逐条打勾。三项各自计分，不合并成一个"好/不好"。

**标注**：✅ 本轮实测通过｜⚠️ 有条件通过（列出保留项）｜⛔ 未过｜— 本轮未测（只校验了路由）

---

## 一、触发（description 覆盖）

静态可查，不代真实召回：description 里必须能对上用户的原话词。

| 用户原话里的词 | description 是否覆盖 |
|---|---|
| 纹样 / 图案 / 印花 / 提花 / 刺绣 | ✅ |
| 线稿 / 线描 / 黑白稿 | ✅ |
| 母题 / 骨格 / 二方连续 / 四方连续 | ✅ |
| 配色方案 / 改色 / 发灰 / 太满 / 拼接不上 | ✅ |
| 丝巾 / 抱枕 / 礼盒 / 冰箱贴 / 云肩 / 首饰 | ✅（承载方式，非设计目标，已在 description 里写明） |
| 展示视频 / 动起来 / 7 秒片 | ✅（"成品展示短视频（5–10 秒）"） |
| 只给大方向（东方 / 敦煌 / 清冷 / 复古 / 潮 / 手作） | ✅（写了"先翻成参数再给建议"） |
| 零想法（随便来个 / 给我点灵感 / 你看着办） | ✅（写了"给三个方向让挑，不追问问卷"） |
| 金苍绣 / 宋锦 / 蜡染扎染 | ✅ |
| 版权 / 能不能商用 | ✅ |

> 真实召回率只能在宿主里反复触发才测得出来；这张表只保证"字面入口不漏"。

## 四、本轮实测记录（2026-11-26，Seedream 5.5，1:1）

按 E3 的线稿模板真跑，再沿"线稿 → 上色 → 载体"接两步，验证链路能不能一路带下去。

| 环节 | 产物 | 判定 |
|---|---|---|
| **线稿（情形 A）** | 宋式折枝四方连续，散点式斜向点阵，半错位 1/2，游丝描式 | 单色白底 ✅；100% 放大抽检未见断口 ✅；三级线宽可分 ✅（主轮廓粗于叶脉）；单位完整、无半朵花 ✅；**接缝 ⚠️**：四边墨段在左右/上下能大体对上，但 2×2 目视有枝干在缝上"半截"的观感，须按 `lineart-method.md` §3.1 做 4×4 人工复核 |
| **上色（情形 C）** | 敦煌矿物色六色平涂，墨线勾边 | 结构锁定 ✅（同布局、同元素、同位置，未被重画）；无渐变无体积 ✅；色数 ≈ 6 ✅（没冒出第 9 色） |
| **载体（场景六 6A）** | 45×45 抱枕静物 | 纹样可识别、构图一致 ✅；无人无手无文字 ✅；**比例被整体放大**（整幅降维的正常取舍，不是重绘）；底色略偏浅 |

**结论**：这条链在"线稿 → 上色"两段上稳定，"上色 → 载体"稳定但会放大比例；**唯一不稳定的是四方连续接缝**——单张看没问题，拼起来才露，和 checklist 里"只做第一层会崩"的判断一致。

## 五、本轮由此发现并修掉的缺陷

| 编号 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **D1** | 线稿模板同时要求"四周留 10–20% 安全边、不顶到画幅边缘"和"四边可无缝拼接" | 两条互斥：连续类必须**触边出血**才能拼，留安全边就拼不上 | 改成条件句：单独/适合纹样留安全边；二方/四方连续不留、必须出血，并要求触边元素在对面同位置接上 |
| **D2** | 同一份技能里"第零步"指接单分流（SKILL），又指线稿（`prompt-scenes.md`）；SKILL 另有一套 0–13 步流程表 | 两套编号并存，用户说"跳到第 3 步"时会有歧义 | SKILL 四个数字小标题改为不带编号的名称；"第零步"只保留给接单分流之外的含义统一为"第 0 步 = 线稿" |
| **D3** | `禁止事项 9` 要求"未实跑标【未实跑】"，与"不产出任何占位标记""不出现打样回填"冲突 | 上一版工艺验证口径的残留 | 改为"没跑过的按画面效果调、不写成实测结论；交付里不打这类标记" |
| **D4** | README 快速开始写"Agent 先反问你 2–3 个问题"、配色写"70/20/10" | 与 SKILL「给方案不问问题」相反；与 1.5.1 修正后的面积配比不一致 | 示例改为"直接给三个方向让你挑"、配色改引用三层比例的实际数值 |
| **D5** | E6 出图后没说明"降维到哪一级、比例为什么变了"（抱枕实跑时纹样被整体放大） | 输出规范里没有承载这张信息的字段 | SKILL 输出标准化新增 `【降维级别】整幅 / 单元 / 剪影`，要求比例变化一并写明 |
| **D6** | 6B 礼盒模板同时写"仅展示正面"和"其余面露边" | 同一句里两条相反指令，实测被拍成三面同框 | 改为"只拍正面，其余面不要进入画面"，并注明同框多面会被拍成三面 |
| **D7** | 7A 云肩悬挂时颈部开口露出木质衣架杆，读起来像"没脖子的人台" | 只写了无人物，没约束颈部开口 | 模板改为"平铺展开 / 挂于无头人台或衣架，颈部开口处只见缎面内衬"，并注释"宁可用平铺" |
| **D8** | 情形 B 声称写 `two-tone` 就"稳定得到实心黑线" | 实测做不到纯两值：灰阶像素 8.7% → 7.4%，抗锯齿边缘仍在 | 改为"能明显压灰但不等于纯两值；要真两值得自己阈值二值化或矢量重描" |

## 六、还没覆盖的

- **真实触发召回**：只能靠反复对话触发，本表只校验字面词是否覆盖。
- **E5 反推线稿、E7 云肩、礼盒/冰箱贴/首饰、E8 视频**：本轮没跑，仍按旧标注（`product-prompts.md` / `showcase-video.md` 的「实测状态」节）。
- **产出合格率的主观项**（"高级感""不俗气"）：机器判不了，只能在固定判据上打分（单色、闭合、色数、无人物、无文字），其余交人看。

**顺带查到的触发冲突（不属于 PTS，属 `fashion-studio`）**

`fashion-studio` 的 description 里，触发词列表包括了"纹样、图案"，同一条又写"纹样走 `pattern-texture-skill`"。用户说"出个纹样"时两个技能的 description 同时命中——谁赢取决于宿主排序，不取决于你的意图。这是本轮唯一测到的**真实触发风险**，而且是另一份技能里的，PTS 本身没错。建议把 FS 触发词里的"纹样、图案"删掉（保留"纹样走 PTS"那句），或者改成"服装企划/款式图/大片"这类专属词。改动涉及另一份技能，等你点头。

**一句话结论**：反推线稿这条链"结构能对齐、两值做不到"；云肩/礼盒/首饰三件都能出、且都不出人物，但礼盒和云肩各有一处模板级的自相矛盾或漏约束，已经改掉。
